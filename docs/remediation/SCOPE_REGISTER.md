## ۱. وضعیت فعلی مخزن و محیط اجرا

### ۱.۱. تفاوت‌های کلیدی بین کامیت مبنای گزارش و وضعیت فعلی (`HEAD`)
بررسی لاگ‌های گیت نشان می‌دهد پس از اسنپ‌شات اولیه گزارش، کامیت‌هایی در مخزن ثبت شده است:
- `6bd0bf3`: رفع مشکل فال‌بک داینامیک فرستنده، سقف روزانه و کول‌داون فرستنده
- `497a5b6`: افزودن `import os` در ماژول llm
- `792f631`: استفاده از ProxyHandler در ارتباط با LLM
- `9a551c0`: نگاشت مدل `gpt-6-luna` به `gemini-3.5-flash-lite`
- `3b592ec` و `88f403c`: افزودن کنترل‌های سشن و دکمه ریست کول‌داون در فرستنده‌ها
- `4687e2e`: بازآرایی پرامپت تریپلت نیاز در collector توییتر

**قاعده حاکم:** هیچ‌یک از تغییرات موجود کاربر نباید بازنشانی (reset)، حذف یا رونویسی (overwrite) شوند.

### ۱.۲. محیط اجرا و سرویس‌ها
- **پایتون:** Python 3.12.16 درون ایمیج داکر `moshtari-yab:latest` (مطابق CI گیت‌هاب).
- **پایگاه داده:** PostgreSQL 16 همراه با افزونه `pgvector` (`pgvector/pgvector:pg16`).
- **اجرای تست‌ها:**
  * تست‌های Pytest (۳۹۴ تست در مسیرهای `telegram_crawler`, `need_engine`, `workers`, `x_ingest`, `shared`, `instagram_discovery`). در اجرای فعلی با دیتابیس تست: **۳۵۳ تست پاس‌شده، ۴۱ تست Skip (مربوط به نشست تلگرام و اتصال شبکه)، ۰ خطا**.
  * تست‌های جنگو (`python manage.py test apps`): ۱۹۰ تست موجود. برخی تست‌های قدیمی به دلیل متغیرهای محیطی یا نیازمندی‌های ماک در حال حاضر باگ‌های شناخته‌شده دارند که در تسک‌های بعدی تفکیک و تثبیت می‌شوند.

## ۲. رده‌بندی اجزای پروژه (Classification Matrix)

تمامی پوشه‌ها و ماژول‌ها در ۴ دسته مشخص رده‌بندی شدند:
1. **ACTIVE:** مسیرهای فعال در حال اجرا در پروداکشن/سرویس‌های داکر
2. **LEGACY-FROZEN:** مسیرهای قدیمی که به دستور صریح مالک محصول منجمد هستند و نباید تغییر، حذف یا ارتقا داده شوند
3. **SHARED:** کتابخانه‌ها، دیتاست‌ها و جداول مشترک بین سرویس‌ها
4. **BLOCKED / DEFERRED:** کارهایی که تا زمان تصمیم‌گیری یا اجرای تسک‌های پیش‌نیاز مسدودند

| مسیر / ماژول | دسته‌بندی | توضیحات و شواهد | مالک / وضعیت تغییر |
|---|---|---|---|
| `apps/accounts/` | **ACTIVE** | مدیریت کاربران، تننت‌ها، فرم‌ها و اکانت‌های متصل | مجاز برای اصلاحات امنیتی و ایزولاسیون تننت |
| `apps/discovery/` | **ACTIVE** | هسته فرصت‌ها، اسکرپرهای اینستاگرام و مدل‌های موتور | مجاز با حفظ سازگاری داده |
| `apps/products/` | **ACTIVE (حذف B2C)** | کاتالوگ و دسته‌بندی کالا؛ مسیرهای عمومی کارت/سفارش مشتری نهایی طبق دستور حذف می‌شوند | مجاز برای حذف B2C و ایمن‌سازی پنل داخلی |
| `apps/billing/` | **ACTIVE** | سیستم تراکنش، کیف پول و ثبت هزینه مصرف هوش مصنوعی | مجاز برای اتصال به صف و اتمیک‌سازی تراکنش‌ها |
| `apps/core/` | **SHARED** | ماژول‌های روتر مدل، توابع کمکی مشترک و دیتابیس | با احتیاط و تست رگرسیون |
| `need_engine/` | **ACTIVE** | موتور تطبیق نیاز، هوش مصنوعی، وکتورهای pgvector | مجاز برای اصلاح هزینه‌ها و صف انتظار |
| `telegram_crawler/` | **ACTIVE** | کراولر گروه‌های تلگرام و ذخیره پیام‌ها | مجاز برای مهار و تست‌های ایزوله |
| `workers/x_collector/` | **ACTIVE** | جمع‌آوری توییت‌ها بر اساس دسته‌بندی | فعال |
| `workers/ig_collector/` | **ACTIVE** | جمع‌آوری پست‌ها و کامنت‌های اینستاگرام | فعال |
| `workers/telegram_config_bot.py` | **ACTIVE (نیاز به Guard)** | ربات تلگرام پیکربندی (یافته R03) | فقط افزودن Allowlist و احراز هویت fail-closed |
| `instagram_engine/` | **LEGACY-FROZEN** | کدهای اولیه SQLAlchemy و مدل‌های موازی جدول `ig_accounts` و `leads` (یافته R25) | **ممنوع‌التغییر (FROZEN)**؛ بدون مایگریشن، بدون حذف |
| `x_ingest/` | **ACTIVE** | اعتبارسنجی و لود فایل‌های jsonl توییتر | فعال |
| `shared/collector_kit/` | **SHARED** | استیت استور SQLite/Postgres برای کراولرها | تغییرات با رعایت قرارداد مشترک |
| `xray/` | **ACTIVE INFRA** | مدیریت کانفیگ پروکسی V2Ray/Xray (یافته R04) | خروج پسورد هاردکدشده و مدیریت با متغیرهای امنیتی |
| `data/` | **SHARED DATA** | داده‌های پایه، لکسیکون‌های فارسی و داده‌های گلدن | فقط خواندنی در تست‌ها |

## ۴. مسیر Backup / Restore برای تست‌ها و تغییرات

- برای تمام آزمون‌های واحد و یکپارچگی، تست‌ها روی پایگاه داده موقت (`--keepdb` یا دیتابیس‌های تست مستقل `test_*`) اجرا می‌شوند.
- قبل از هر مایگریشن دیتابیس در مراحل بعدی، اسکریپت پشتیبان‌گیری از اسکیمای فعلی اجرا خواهد شد:
  ```bash
  docker exec moshtari-yab-db-1 pg_dump -U postgres -d customer_yab --schema-only > /app/backups/pre_remediation_schema.sql
  ```
- بازگشت کد بدون تغییرات دیتابیس از طریق `git revert` تمیز و قابلیت Feature Flag انجام می‌شود.
