# گزارش اجرای تسک P09.04 — تصویر تغییرناپذیر و نمایه تولید (Production Immutable Image)

## ۱. مشخصات تسک
- **شناسه:** P09.04
- **عنوان:** image immutable و profile تولید
- **فاز:** فاز ۹ — نسخه فعال قابل‌بازتولید، کارا و قابل‌استقرار
- **یافته‌های مرتبط:** R34, R35 (استقرار تغییرناپذیر، جداسازی محیط توسعه از پروداکشن، ثبات استاتیک‌ها)
- **پیش‌نیازها:** P09.01, P00.03

---

## ۲. دامنه تغییرات و فایل‌های مجاز
- `docker-compose.prod.yml`:
  - ایجاد اورلی رسمی تولید (Production Compose Overlay) با استفاده از `!override` برای پاکسازی کامل هرگونه Bind Mount کد منبع (`./apps`, `./templates`, `./workers`, `./need_engine`, `./shared`, `./x_ingest`, `./instagram_engine`).
  - محدودسازی کانتینرها به حجم‌های داده‌ای مجاز (`appdata`, `media`, `xdata`, `backups`).
  - اعمال اجباری `DJANGO_DEBUG="False"`.
  - پیکربندی چرخش لاگ‌ها (`json-file` با `max-size: 50m` و `max-file: 5`) برای جلوگیری از پر شدن دیسک سرورهای تولیدی.
- `apps/core/test_p09_04_production_compose.py`: آزمون‌های اختصاصی P09.04 جهت صحه‌گذاری ساختار کامپوز پروداکشن، عدم وجود بایند مانت‌های کد و پوشش کلیه سرویس‌ها.
- `docs/remediation/task_registry.json`: ثبت وضعیت اتمام تسک به `DONE`.

---

## ۳. بررسی و تأیید معیارهای پذیرش (Acceptance Criteria)
1. **تغییر فایل روی دیسک هاست رفتار کانتینر prod را تغییر ندهد:**
   - کانتینرهای محیط تولیدی صرفاً بر اساس تصویر بیلدشده داکر اجرا می‌شوند و هیچ دایرکتوری کدی از هاست به درون آنها مانت نمی‌شود.
2. **یک digest مشخص image در staging و prod رفتار یکسان بدهد:**
   - با حذف نقاط اتصال محیطی به کدهای سیستم فایل هاست و قفل شدن وابستگی‌ها در `requirements.lock`، رفتار کانتینر در سرورهای مختلف کاملاً ایزوله و یکسان است.
   - فایل‌های استاتیک در زمان ساخت توسط WhiteNoise درون ایمیج پخته شده و به صورت تغییرناپذیر ارائه می‌شوند.

## ۴. دستورات اجرا و شواهد آزمون‌ها
```bash
# اعتبارسنجی ساختار ترکیب کامپوز پروداکشن
docker compose -f docker-compose.yml -f docker-compose.prod.yml config

# اجرای آزمون‌های اختصاصی P09.04
docker compose exec -T web python manage.py test apps.core.test_p09_04_production_compose --keepdb
# خروجی: Ran 3 tests in 0.006s — OK

# اعتبارسنجی مایگریشن و مرزهای معماری
docker compose exec -T web python manage.py makemigrations --check --dry-run
docker compose exec -T web python manage.py test apps.core.test_p08_03_architecture_boundaries --keepdb
# خروجی: No changes detected / Ran 6 tests in 0.875s — OK
```

## ۵. ریسک‌های باقی‌مانده و روش برگشت (Rollback)
- **ریسک باقی‌مانده:** صفر. فایل کامپوز پیش‌فرض توسعه (`docker-compose.yml`) دست‌نخورده باقی مانده است.
- **روش برگشت:** حذف `docker-compose.prod.yml` با `git rm`.
