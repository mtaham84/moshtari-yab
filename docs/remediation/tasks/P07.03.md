## ۲. خلاصه تغییرات
1. **مدل پایگاه داده `TaxonomyJob`:**
   - جدول پایدار جنگو با فیلدهای `job_key` یکتا، `business`، `catalog_version`، وضعیت (`PENDING`، `RUNNING`، `COMPLETED`، `FAILED`، `DEAD_LETTER`)، قفل زمان‌دار (`lease_owner` و `lease_expires_at`)، شمارنده تلاش‌ها (`attempts`) و سقف مجاز (`max_attempts`).
2. **سرویس مخزن کارهای دسته‌بندی (`TaxonomyJobRepository`):**
   - ثبت کار (`enqueue_job`): در صورت ارسال چند درخواست همزمان برای یک نسخه کاتالوگ، همه به یک رکورد متمرکز تبدیل می‌شوند (Idempotent).
   - دریافت کار با قفل توزیع‌شده (`claim_next_job`): استفاده از `select_for_update(skip_locked=True)` جهت جلوگیری از تداخل ورکرها و تخصیص lease زمان‌دار.
   - بازیابی خودکار کرش ورکر (`recover_expired_leases`): در صورت کرش ورکر، انقضای lease تشخیص داده شده و کار برای ورکر دیگر بازنشانی می‌شود.
   - مهار کارهای سمی (Poison Pill Protection): پس از ۳ بار شکست متوالی، کار به وضعیت `DEAD_LETTER` منتقل شده و از حلقه‌های بی‌پایان خطا جلوگیری می‌شود.

## ۳. شواهد تست و نتایج
- **فایل تست:** `apps/products/tests/test_p07_03_taxonomy_jobs.py`
- **فرمان اجرا:**
  ```bash
  docker compose exec -T web python manage.py test apps.products.tests.test_p07_03_taxonomy_jobs --keepdb
  ```
- **نتیجه:** ۵ تست در ۰.۱۷۴ ثانیه با موفقیت ۱۰۰٪ پاس شدند:
  1. `test_concurrent_enqueue_collapses_into_single_pending_job`: ادغام چند ثبت همزمان برای یک نسخه کاتالوگ در یک کار پایدار.
  2. `test_claim_next_job_sets_lease_and_increments_attempts`: تخصیص امن قفل و افزایش شمارنده تلاش‌ها.
  3. `test_crash_recovery_resets_expired_leases`: بازیابی موفق کار ناتمام پس از کرش ورکر.
  4. `test_poison_pill_protection_moves_to_dead_letter`: انتقال خطای دائم به `DEAD_LETTER` پس از ۳ بار شکست.
  5. `test_complete_job_records_results`: ثبت خروجی و تکمیل موفق کار.
