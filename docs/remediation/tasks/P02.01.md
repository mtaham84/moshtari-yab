# گزارش اجرای تسک P02.01 — مرز API پیشنهاد پولی بدون بازکردن مصرف

## ۱. مشخصات تسک
- **شناسه:** P02.01
- **عنوان:** مرز API پیشنهاد پولی بدون بازکردن مصرف (Securing Paid Suggestion API Boundary without Opening Consumption)
- **فاز:** فاز ۲ — امنیت وب، اعتبارسنجی و حفاظت اسرار
- **یافته‌های مبنا:** R07
- **پیش‌نیازها:** P01.05, P00.02
- **وضعیت:** DONE

---

## ۲. شرح مشکل و رفتار مطلوب
- **مشکل:**
  - طبق یافته R07، در مسیر `api_suggest_category`، درخواست‌های GET می‌توانستند در صورت عدم تطابق هیوریستیک، مستقیماً مدل‌های LLM پولی (`chat_json`) را فراخوانی کنند که ریسک تحمیل هزینه مالی از طریق ترافیک عمومی وب را به همراه داشت.
  - کاربران ناشناس یا بدون کسب‌وکار می‌توانستند منابع محاسباتی را درگیر کنند.
  - هیچ سقف مشخصی برای طول نام و توضیحات ورودی وجود نداشت.
- **رفتار مطلوب:**
  1. درخواست‌های متد GET صرفاً خواندنی، مبتنی بر تطابق هیوریستیک محلی، رایگان و بدون هیچ‌گونه فراخوانی LLM یا جهش داده باشند (`allow_ai=False`).
  2. درخواست‌های هوش مصنوعی نیازمند متد POST، کاربر احرازشده دارای کسب‌وکار فعال و توکن معتبر CSRF باشند.
  3. اعمال محدودیت ورودی (طول نام حداکثر ۲۵۵ کاراکتر و طول توضیحات حداکثر ۲۰۰۰ کاراکتر).
  4. طبق گام ۳ تسک، تا زمان اتصال گیت و دفترکل مالی در فاز ۶، درخواست‌های هوش مصنوعی پاسخ قراردادی صف (`status: queued`) دریافت کنند و اجازه مصرف مستقیم نامحدود صادر نشود.
  5. پاسخ مدل هوش مصنوعی تحت هیچ شرایطی نتواند دسته‌بندی اختصاصی سایر مستأجرها را انتخاب یا بازگرداند (دفاع لایه‌بندی‌شده یافته R13).

## ۳. تغییرات انجام‌شده
1. **`apps/products/services.py`**:
   - به تابع `suggest_category_for_product` پارامتر `allow_ai: bool = False` اضافه شد. در صورت عدم فعال بودن این پرچم، پس از ارزیابی هیوریستیک سریعاً `None` برگردانده شده و ورود به بلوک `chat_json` به طور کامل مسدود است.
   - اضافه شدن گیت دفاعی برای پاسخ‌های هوش مصنوعی: اگر شناسه برگردانده‌شده از مدل متعلق به کسب‌وکار دیگری باشد (`matched_cat.business_id != business.id`)، پاسخ بلافاصله نادیده گرفته شده و `None` برگردانده می‌شود.
2. **`apps/products/views.py`**:
   - در ویوی `api_suggest_category`:
     - مسدودسازی دسترسی کاربران ناشناس (۴۰۱) و بدون کسب‌وکار (۴۰۳).
     - تفکیک رفتار GET و POST: در GET متغیر `request_ai=False` تثبیت می‌شود.
     - اعتبارسنجی طول نام (حداکثر ۲۵۵) و توضیحات (حداکثر ۲۰۰۰) با خطای ۴۰۰.
     - بازگرداندن قرارداد پاسخ در صف (`status: queued`) برای درخواست‌های POST نیازمند هوش مصنوعی تا زمان ادغام ماژول مالی در فاز ۶.
3. **`apps/core/test_p02_01_paid_suggestion_boundary.py`**:
   - نگارش سوئیت آزمون با ۷ سناریوی امنیتی:
     - رد درخواست ناشناس (۴۰۱) بدون فراخوانی LLM.
     - رد کاربر بدون کسب‌وکار (۴۰۳) بدون فراخوانی LLM.
     - اجرای GET بدون تطابق هیوریستیک با نتیجه `no_match` و اثبات عدم فراخوانی `chat_json`.
     - مسدودسازی POST فاقد توکن معتبر CSRF توسط گارد امنیتی جنگو (۴۰۳).
     - مهار ورودی‌های فراتر از سقف مجاز (طول نام > ۲۵۵ و توضیحات > ۲۰۰۰) با خطای ۴۰۰.
     - بازگشت پاسخ قراردادی `status: queued` برای درخواست‌های نیازمند هوش مصنوعی بدون مصرف مستقیم.
     - اثبات ناتوانی مدل در انتخاب یا انتساب دسته‌های اختصاصی سایر مستأجرها.
