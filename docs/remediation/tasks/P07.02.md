## ۲. خلاصه تغییرات
1. **حذف اجرای DDL از مسیر رکوئست‌های فعال:**
   - تغییر سازنده `Store`: جداسازی مقداردهی اولیه پایگاه داده از رکوئست‌های فعال با پارامتر `create=False`.
   - در حالت اجرای عادی رکوئست‌ها، صفر دستور DDL (نظیر `CREATE TABLE IF NOT EXISTS`، `CREATE EXTENSION`، `CREATE INDEX`) اجرا می‌شود؛ بنابراین احتمال قفل‌شدن متادیتای جداول یا خطا در صورت اتصال با کاربر کم‌مجوز (بدون دسترسی DDL) به‌طور کامل حذف شد.
2. **بررسی پیش‌پرواز فقط‌خواندنی (`_preflight_schema`):**
   - جایگزینی DDL با اعتبارسنجی خواندنی از `information_schema.tables` جهت اطمینان از وجود جداول ضروری (`kv`, `needs`, `costs`, `opportunities`, `operation_idempotency`).
3. **متد مستقل بوت‌استرپ و دستور مدیریتی جنگو:**
   - ارائه متد `Store.bootstrap_schema()` برای اجرای صریح میگریشن‌ها تنها در فرآیندهای راه‌اندازی و نگهداری.
   - ایجاد دستور مدیریتی `python manage.py migrate_engine_schema [--schema=...]` برای مدیریت متمرکز و کنترل‌شده اسکیما.

## ۳. شواهد تست و نتایج
- **فایل تست:** `apps/core/test_p07_02_decouple_ddl.py`
- **فرمان اجرا:**
  ```bash
  docker compose exec -T web python manage.py test apps.core.test_p07_02_decouple_ddl --keepdb
  ```
- **نتیجه:** ۴ تست در ۰.۳۷۴ ثانیه با موفقیت ۱۰۰٪ پاس شدند:
  1. `test_runtime_create_false_executes_zero_ddl_statements`: اثبات جاسوسی و اعتبارسنجی صفر بودن دستورات DDL در مسیر اجرای `create=False`.
  2. `test_preflight_schema_fails_when_tables_missing`: پرتاب استثنای صریح `RuntimeError` در صورت ناقص بودن اسکیما بدون تلاش برای ساخت خودکار در رکوئست.
  3. `test_bootstrap_schema_and_preflight_validation`: بوت‌استرپ صریح جداول و تایید موفقیت preflight.
  4. `test_migrate_engine_schema_management_command`: اجرای موفق دستور مدیریتی `migrate_engine_schema`.
- **اجرای تست‌های need_engine:** ۶۵ تست با قبولی ۱۰۰٪ پاس شدند.
